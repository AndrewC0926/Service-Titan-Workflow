How this is built
Rank inputs shown, not a black-box score Sorted by (EUI vs. type median + age credit), shown below as their own columns, never folded into one opaque number.
 
EUI vs. type median — the building's weather-normalized Site EUI divided by the MEDIAN for its own property type among in-territory buildings (a 1980 office and a 1980 warehouse don't share a normal EUI range, so this is always computed within type). 1.30x means 30% above its type's median; this is a ratio, not a percentile rank, so a building at 3x median clearly outranks one at 1.2x even if both are "top of their type."
 
Age credit — full credit (1.0) for Year Built 1985–2012, tapering linearly to 0 by 1975 on the early side and by 2018 on the late side. Built before 1975 gets NO credit, not full credit: by now, a pre-1975 building's original equipment has almost certainly already been replaced at least once (typical commercial HVAC service life is 15–25 years), so Year Built alone tells you nothing about what's actually installed today — genuinely unknown, not "assumed old."
 
A building missing Year Built or EUI simply has no value for that half — never guessed at, never defaulted to a mid-point. Ties break on GFA, larger first — a bigger building is a bigger order.
How this is built
GFA floor and an EUI-ratio anomaly cutoff AB 802 itself only covers buildings 50,000 sq ft and larger — a row on file below 20,000 sq ft (or with no GFA stated at all) is dropped before ranking even starts, not shown at all: it's treated as a data error in the source file, not a real building, and it's also excluded from every property type's median so one bad GFA value can't distort what every other row in its type is ranked against. Separately, a row whose Site EUI comes out above 5x its type's median is pulled out of the ranked list below into its own "Data anomaly, verify before calling" table instead — plausibly a real building, but a >5x-median EUI is more often a meter or unit mismatch than a genuine finding, and letting one dominate the top of the list on a number that likely isn't real would bury the genuine leads under it.
How this is built
Assessor match is a building match, not an owner match "Assessor match" links a row to a matched RetrofitBuilding record — lat/long within 30m first, normalized address second (see /assumptions for the measured rate and method breakdown) — never an owner. No free, bulk-queryable LA County assessor owner-name source exists at all (see RetrofitBuilding's own docstring); this board shows "no owner data available" for exactly that reason, on every row, permanently. Where a row also matches an LA EBEWE benchmark filing by address, that filing's own self-reported organization field is shown labeled "benchmarking filer" — the entity that filed the EBEWE benchmark, not a verified owner. Where neither exists but the Property Name itself reads like an organization (contains LLC, Inc, Hospital, University, District, County, City of, Church, or School), that name is shown labeled "name on filing" instead — a hint worth calling, never a claim that it IS the owner. Both joins, and this whole population, are LA County only — the only county this app's assessor/EBEWE data covers; outside LA, a row stands alone with its Property Name.
How this is built
Defaults to DMG-relevant property types Office, medical office, hospital, K-12 school, college/university, laboratory, data center, warehouse/distribution, manufacturing/industrial, hotel, and retail — an allowlist verified against the real property types on file, not a guess (golf/country club rows carry "Other - Recreation" or similar, casino rows carry "Casino," worship rows "Worship Facility," parking rows "Parking" — none of those, or any other Portfolio Manager "Other -" catch-all, are in the allowlist). Multifamily Housing is NOT in the default either, as of 2026-09-07 — still selectable explicitly below. Pick a specific property type (including an excluded one) or check "show all property types" to see everything.
